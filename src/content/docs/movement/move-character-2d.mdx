<Aside type="tip" title="Short answer">
Use a `CharacterBody2D`. In `_physics_process()`, set its `velocity`, then call `move_and_slide()`.
</Aside>

## Set up the scene

Create a new scene with this structure:

<SceneTree tree={`
  Player: CharacterBody2D [script] "the script goes here"
    Sprite2D: Sprite2D
    CollisionShape2D: CollisionShape2D "give it a shape"
`} />

Give the `Sprite2D` a texture. The default `icon.svg` is fine for now. Then select the `CollisionShape2D`, pick a shape in the Inspector such as `RectangleShape2D` or `CapsuleShape2D`, and resize it to fit the sprite.

## Add the script

Attach a script to `Player`:

<Tabs syncKey="lang">
<TabItem label="GDScript">

```gdscript title="player.gd"
extends CharacterBody2D

const SPEED := 300.0

func _physics_process(_delta: float) -> void:
	var direction := Input.get_vector("ui_left", "ui_right", "ui_up", "ui_down")
	velocity = direction * SPEED
	move_and_slide()
```

</TabItem>
<TabItem label="C#">

```csharp title="Player.cs"
using Godot;

public partial class Player : CharacterBody2D
{
    private const float Speed = 300.0f;

    public override void _PhysicsProcess(double delta)
    {
        Vector2 direction = Input.GetVector("ui_left", "ui_right", "ui_up", "ui_down");
        Velocity = direction * Speed;
        MoveAndSlide();
    }
}
```

</TabItem>
</Tabs>

Run the scene. The arrow keys move the player in eight directions, and it stops at walls instead of passing through them.

`Input.get_vector()` returns a vector with a length of 1 or less, so moving diagonally isn't faster than moving straight.

## Use WASD too

Open **Project → Project Settings → Input Map** and add four actions: `move_left`, `move_right`, `move_up`, `move_down`. Assign both the arrow keys and WASD to them, then use those names instead of the `ui_` ones:

```gdscript title="player.gd" del={1} ins={2}
var direction := Input.get_vector("ui_left", "ui_right", "ui_up", "ui_down")
var direction := Input.get_vector("move_left", "move_right", "move_up", "move_down")
```

The `ui_` actions are meant for menus. Keeping your own actions separate means a UI change later won't break your movement.

## Common mistakes

:::note[Multiplying by delta]
`move_and_slide()` already accounts for frame time. `velocity = direction * SPEED * delta` makes the character crawl.
:::

:::note[Changing position directly]
`position += direction * SPEED * delta` moves the node but skips collision checks, so the character goes through walls.
:::

:::note[Warning icon on the node]
A yellow warning next to `Player` in the Scene dock means the `CollisionShape2D` is missing or has no shape. Without one, nothing collides.
:::

:::note[Using _process]
Put movement in `_physics_process()`, not `_process()`. Otherwise it can jitter and collide inconsistently.
:::
